# Expose an Ash knowledge base over a strict JSON:API HTTP interface

## Background

`/home/user/kbapi` is an Elixir project (OTP app `:kbapi`, Elixir 1.18.4 / OTP 27.3.4) built on **Ash Framework 3.31** with **ash_json_api 1.7**, `plug` and `open_api_spex` already declared as dependencies and pre-compiled offline.

The project already contains a working data layer and nothing else:

- `Kbapi.Knowledge` — the Ash domain, listing all five resources.
- `Kbapi.Knowledge.Author` — `name`, `handle`, `bio`, `role` (`:reader | :editor | :admin`), `has_many :articles`.
- `Kbapi.Knowledge.Article` — `title` (required, min length 3), `slug` (required), `body`, `status` (`:draft | :published | :archived`, default `:draft`), `rank` (integer, default 0), `word_count` (integer, default 0); `belongs_to :author` (writable), `has_many :comments`, `many_to_many :tags` through `Kbapi.Knowledge.ArticleTag`; a public `comment_count` count aggregate.
- `Kbapi.Knowledge.Tag` — `name`, `slug`, `many_to_many :articles`.
- `Kbapi.Knowledge.Comment` — `body` (required, min length 2), `approved` (boolean, default `false`), `belongs_to :article` (writable).
- `Kbapi.Knowledge.Fixtures` — deterministic seed data plus `reset!/0` and the `author_id/1`, `article_id/1`, `tag_id/1`, `comment_id/1` lookup helpers. **Do not modify this module.**

All resources use `Ash.DataLayer.Ets` with `private? true`, so every process has its own isolated store.

There is no HTTP layer at all. Build one.

## Requirements

Build a JSON:API-conformant HTTP interface over these resources, mounted at `/api`, together with the authorization and content-negotiation behaviour described below. Every requirement is stated as observable request/response behaviour; how you get there is up to you.

### Entry point

- `Kbapi.Api.Endpoint` must be a `Plug` (it must export `init/1` and `call/2`). The verifier builds requests with `Plug.Test.conn/2,3` and invokes `Kbapi.Api.Endpoint.call(conn, Kbapi.Api.Endpoint.init([]))` **in the calling process** — no network listener is started and none may be required.
- `Kbapi.Api.Router` must be the JSON:API router module that `Kbapi.Api.Endpoint` serves under the `/api` path prefix.
- Every JSON:API response must be sent with the `application/vnd.api+json` content type and must be a JSON:API document: successful documents carry the top-level `jsonapi` member `{"version": "1.0"}` and a top-level `links.self` equal to the requested absolute URL; `self`/`related` links are absolute URLs derived from the request plus the `/api` prefix.

### JSON:API resource types

`Article` is `"article"`, `Author` is `"author"`, `Tag` is `"tag"`, `Comment` is `"comment"`. `ArticleTag` is not exposed.

### Routes (all paths below are relative to the `/api` prefix)

Articles, under the base path `/articles`:

| Method | Path | Behaviour |
| --- | --- | --- |
| GET | `/articles` | collection of articles |
| GET | `/articles/:id` | one article |
| POST | `/articles` | create an article |
| PATCH | `/articles/:id` | update an article |
| DELETE | `/articles/:id` | destroy an article |
| PATCH | `/articles/:id/publish` | run the article `:publish` action |
| GET | `/articles/:id/comments` | the article's comments, as full `comment` resource objects |

| DELETE | `/articles/:id/relationships/tags` | remove the supplied tags from the article |
| POST | `/articles/reindex` | run the article `:reindex` generic action |
| GET | `/articles/tally/:status` | run the article `:tally` generic action |

### Article representation

- By default an `article` resource object's `attributes` member contains exactly `title`, `slug`, `body`, `status`, `rank`, `word_count` and `author_id`. `comment_count` is **not** rendered by default but must be selectable via a sparse fieldset (`?fields[article]=title,comment_count`), which must also restrict the rendered attributes to exactly what was requested.
- The `author` relationship must always carry its resource-identifier `data` member, even when the caller does not ask for it. `tags` and `comments` must **not** carry a `data` member unless the caller requests them via `include`.
- An article resource object must carry a `links.self` pointing at its own `GET /api/articles/:id` route, `relationships.comments.links.related` pointing at `GET /api/articles/:id/comments`, and `relationships.tags.links.self` pointing at `GET /api/articles/:id/relationships/tags`.
- The includable relationship paths for `article` are `author`, `author.articles`, `tags` and `comments`; the includable path for `comment` is `article`, and for `author` it is `articles`. Any other `include` value must be rejected with HTTP 400 and error `code` `"invalid_includes"` and `source.parameter` `"include"`.

### Querying

- `GET /api/articles` must support `sort` (including the `-` descending prefix) over the article's own attributes, and must reject an unknown sort field with HTTP 400, error `code` `"invalid_sort"` and `source.parameter` `"sort"`.
- `GET /api/articles` must support filtering on its own attributes (`filter[status]=published`), on a related resource's attributes (`filter[author][handle]=ada`) and with comparison operators (`filter[word_count][greater_than]=500`). Filtering on a field that does not exist must produce HTTP 400.
- `GET /api/articles` must be offset-paginated: `?page[limit]=2` returns two records, reports `meta.page` as `{"limit": 2, "offset": 0}`, sets `links.prev` to `null` and provides a `links.next` that carries `page[offset]=2`; following that link returns the next window and reports `meta.page` as `{"limit": 2, "offset": 2}`.
- `GET /api/tags` must **ignore** `filter` and `sort` query parameters entirely (it must answer 200 with the full unsorted collection rather than filtering, sorting or erroring).

### `/api/feed`

- Serves articles through a dedicated `Kbapi.Knowledge.Article` read action named `:feed` that is **keyset**-paginated only (offset paging must not be available on it), always paginates, and defaults to a page size of 2.
- Results are ordered by `rank` descending, then by `id` ascending.
- `meta.page` reports only the effective `{"limit": n}`; `links.next` carries a `page[after]=<cursor>` parameter, and following it returns the next window. On the last page `links.next` is `null`.
- `?page[limit]=3` returns three records.
- A cursor that is not a valid keyset must be rejected with HTTP 400 and error `code` `"invalid_keyset"`.

### Writes and error documents

- `POST /api/articles` accepts `title`, `slug`, `body`, `status`, `rank`, `word_count` and `author_id` and answers HTTP 201 with the created resource object.
- A create/update request body whose `data` member has no `type` must be rejected with HTTP 400 and error `code` `"missing_type"` and `source.pointer` `"/data"`.
- A missing required attribute must produce HTTP 400 with error `code` `"required"`, `title` `"Required"` and `source.pointer` `"/data/attributes/<attribute>"`.
- An attribute that violates a constraint must produce HTTP 400 with error `code` `"invalid_attribute"` and `source.pointer` `"/data/attributes/<attribute>"`.
- An attribute the action does not accept must produce HTTP 400 with error `code` `"invalid_body"` and `source.pointer` `"/data/attributes/<attribute>"`.
- `PATCH /api/articles/:id` accepts `title`, `body`, `status`, `rank` and `word_count`, and must additionally accept a `tags` member inside `data.relationships` (a JSON:API to-many linkage array) which **replaces** the article's tags.
- `DELETE /api/articles/:id` answers HTTP 200 with the destroyed resource object.
- The three `/articles/:id/relationships/tags` mutation routes each answer HTTP 200 with the article's resulting tag linkage — a `data` array of resource identifier objects that contain **only** `type` and `id`. A body whose `data` is not an array must be rejected with HTTP 400, error `code` `"invalid_body"` and `source.pointer` `"/data"`; a linkage entry naming a tag that does not exist must produce HTTP 404 with error `code` `"not_found"`.
- Requesting a member that does not exist (e.g. `GET /api/articles/<unknown-uuid>`) must produce HTTP 404 with error `code` `"not_found"`.

### Article actions to add

- `:publish` — an update action reachable at `PATCH /api/articles/:id/publish` that sets `status` to `:published`. If the article's stored `status` is already `:archived` the request must fail with HTTP 400, error `code` `"invalid_attribute"`, `source.pointer` `"/data/attributes/status"` and `detail` exactly `cannot publish an archived article`, and the record must be left untouched.
- `:reindex` — a generic action reachable at `POST /api/articles/reindex` whose HTTP 201 response body is exactly a JSON object with the keys `indexed` (total number of `Article` records), `published` (number whose `status` is `:published`) and `words` (sum of `word_count` over all articles), and nothing else.
- `:tally` — a generic action reachable at `GET /api/articles/tally/:status` that takes the status as a path parameter and answers HTTP 200 with the body `{"result": <number of articles with that status>}`. Supplying the same argument in both the path and the query string must be rejected with HTTP 400 and error `code` `"invalid_query"`; a status outside the allowed set must be rejected with HTTP 400, error `code` `"invalid_argument"` and `source.pointer` `"/data/attributes/status"`.

### Comment actions to add

- `:pending` — a read action reachable at `GET /api/moderation/comments/pending` returning only comments whose `approved` is `false`.
- `:approve` — an update action reachable at `PATCH /api/moderation/comments/:id/approve` that sets `approved` to `true`.

### Actor resolution and authorization

- The request header `x-actor-handle` names the calling actor. Its value must be matched against `Kbapi.Knowledge.Author`'s `handle`; the matching author becomes the Ash actor for the request. A request without the header is anonymous.
- If the header is present but no author has that handle, the request must be answered with HTTP 401, content type `application/vnd.api+json`, and a body that is exactly:

  ```json
  {"errors": [{"code": "unknown_actor", "status": "401", "title": "Unauthorized", "detail": "unknown actor handle <handle>"}]}
  ```

  where `<handle>` is the header value. No Ash action may run for such a request.
- Authorization must be enforced on every request:
  - Reading articles, authors, tags and comments is allowed for everyone, including anonymous callers.
  - Creating, updating, destroying, publishing and mutating the tag linkage of an article requires an actor whose `role` is `:editor` or `:admin`.
  - `:reindex` requires an actor whose `role` is `:admin`.
  - `:tally` is allowed for everyone.
  - Creating a comment is allowed for everyone; updating (including `:approve`) and destroying a comment requires an actor whose `role` is `:editor` or `:admin`.
  - Authors and tags need no authorization.
- Every denial must produce HTTP 403 with error `code` `"forbidden"`, and must not change any stored data.

### Content negotiation and unmatched routes

- An `Accept` header of `application/vnd.api+json; charset=utf-8` must be rejected with HTTP 406 and error `code` `"unacceptable_media_type"`.
- A request body sent with `Content-Type: application/json` must be rejected with HTTP 415 and error `code` `"unsupported_media_type"`.
- A path under `/api` that matches no route must produce HTTP 404 with error `code` `"no_route_found"`.
- A path outside `/api` that matches nothing must be answered by `Kbapi.Api.Endpoint` itself with HTTP 404, content type `application/vnd.api+json`, and a body that is exactly:

  ```json
  {"errors": [{"code": "not_found", "status": "404", "title": "NotFound", "detail": "no route found"}]}
  ```
