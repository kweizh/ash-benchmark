# Expose an Ash knowledge base over a strict JSON:API HTTP interface ## Background `/home/user/kbapi` is an Elixir project (OTP app `:kbapi`, Elixir 1.18.4 / OTP 27.3.4) built on **Ash Framework 3.31** with **ash\_json\_api 1.7**, `plug` and `open_api_spex` already declared as dependencies and pre-compiled offline. The project already contains a working data layer and nothing else: * `Kbapi.Knowledge` — the Ash domain, listing all five resources. * `Kbapi.Knowledge.Author` — `name`, `handle`, `bio`, `role` (`:reader | :editor | :admin`), `has_many :articles`. * `Kbapi.Knowledge.Article` — `title` (required, min length 3), `slug` (required), `body`, `status` (`:draft | :published | :archived`, default `:draft`), `rank` (integer, default 0), `word_count` (integer, default 0); `belongs_to :author` (writable), `has_many :comments`, `many_to_many :tags` through `Kbapi.Knowledge.ArticleTag`; a public `comment_count` count aggregate. * `Kbapi.Knowledge.Tag` — `name`, `slug`, `many_to_many :articles`. * `Kbapi.Knowledge.Comment` — `body` (required, min length 2), `approved` (boolean, default `false`), `belongs_to :article` (writable). * `Kbapi.Knowledge.Fixtures` — deterministic seed data plus `reset!/0` and the `author_id/1`, `article_id/1`, `tag_id/1`, `comment_id/1` lookup helpers. **Do not modify this module.** All resources use `Ash.DataLayer.Ets` with `private? true`, so every process has its own isolated store.
